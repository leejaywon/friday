# Friday 하네스 기획: 직속 비서 + 위임 (2026-11-23, 3차 개정)

## 문제 (사용자 제시)

1. "이거 해야 돼"라고 하면 Done / Tomorrow / Remove 버튼 카드가 바로 떠서 보기 싫다.
2. heads-up이 한 번 오고 끝난다. 얼마나 자주 리마인드할지 AI가 그때그때 판단해야 한다.
3. 과거 대화("우리 CCTV 뭐 봤었지?")를 어떻게 가져오고 기억할지가 엉망이다.
4. 구글 캘린더 일정마다 9분 전 알림이 온다. 보고 알리기만 하는 방식이면 안 된다.
5. 웹서핑을 언제, 어떻게, 얼마나 시도할지 모른다.

다섯 개 모두 하네스 문제다. Friday는 범용 태스크 에이전트여야 하고, 증상마다 기능을 붙이지 않는다.
일의 크기와 종류는 매번 달라지므로, 하네스는 그 일에 맞는 컨텍스트, 도구, 흐름을 준다.

## 구조

**메인은 사용자의 직속 비서다.** 대화, 기억, 할 일, 일정, 스케줄과 간단한 웹 검색을 맡고 빠르게 답한다.
**무거운 일은 위임받은 에이전트가 처리하고**, 메인은 결과만 받아 답한다.

```
사용자 ─ 텔레그램 ─ 메인 비서 ─┬─ 기억 · 할 일 · 일정 · 연락처 · 스케줄 · 파일 전송 · 간단한 웹 검색
                              └─ delegate(목표, 이유, 맥락, 프로젝트?)
                                     │
                                     ├─ 작업 폴더: 브라우저 · 깊은 조사 · 셸 · 파일 (기본 Codex)
                                     └─ 프로젝트: ~/code 저장소, PR 또는 커밋 (기본 Claude Code)
                                     │
                                     └─ 요약 2천 자 이내 + 저장한 파일 + 확인 못 한 것 → 메인

스케줄(1회 / 반복) ─ 메인 대화 또는 임시 대화방에서 실행
리마인더 · 마감 알림 ─ AI 없이 서버가 바로 전송
```

## 근거 (실측, 2026-11-17~22, 228턴)

- 71%(163턴)는 웹, 브라우저, 셸, GitHub 없이 끝난다. 검색 3번 이내의 웹 질문까지 더하면 76%(173턴)를 비서가 직접 처리한다.
- 턴 시간 중앙값: 도구 없음 4.2초, 도구 1~3개 13.8초, 4개 이상 45.8초(p90 161초).
- 새 스레드 시작 입력 약 1만 6천 토큰, 턴 시작 입력 p90 약 5만 6천, 최대 약 20만 토큰.
  스레드 67개 중 13개가 6만, 5개가 10만 토큰을 넘었고 압축은 한 번도 없었다.
- 도구 출력 비중: 브라우저 31%, 웹 검색 27%, 도구 목록 조회 26%. 조회 한 번이 최대 4만 자를 찍는다.
  웹 검색 한 번의 결과는 중앙값 2만 2천 자, 브라우저를 쓴 턴의 페이지 출력은 p90 5만 7천 자다.
- 6만 토큰 제한은 턴이 끝난 뒤에만 확인한다.
- Codex 자체의 `exec` 도구 설명만 2만 6천 자다. Friday가 줄일 수 있는지는 아직 확인하지 못했다.
- 대체 경로(codex exec)는 6일간 2번 쓰였고 같은 모델, 같은 스레드로 이어간다. 우선순위에서 제외한다.

## 결정 사항

### 위임
- 도구는 `delegate` 하나. 비서는 목표, 이유, 필요한 맥락만 넘기고 방법은 위임받은 에이전트가 정한다.
  브라우저, 셸, 코딩, 파일 작업, 여러 출처를 비교하는 조사는 메인에서 하지 않는다.
- 간단한 웹 질문(환율, 날씨, 사실 확인처럼 검색 한두 번으로 답이 나오는 것)은 위임하지 않고 메인이 직접 검색해 답한다.
  경계는 메인이 답을 시작할 때 스스로 판단한다. 별도 분류 호출은 없다.
  메인이 한 턴에 검색을 3번 넘기면 하네스가 위임을 권하는 노트를 넣는다(실측: 웹만 쓴 11턴 중 10턴이 3번 이내).
- 연결은 비동기. 메인은 위임 후 턴을 끝내고 채팅은 비어 있다. 결과가 오면 메인이 이어서 답한다.
  후속 요청은 같은 워커가 페이지 상태를 이어받는다.
- 엔진: 프로젝트 작업은 Claude Code, 브라우저·조사·파일 작업은 Codex가 기본. 사용자가 말하면 그 엔진을 쓴다.
- 파일: 작업마다 임시 폴더. 무엇을 남길지는 워커가 판단해 `files/주제/`로 옮기고 경로를 보고한다.
  나머지는 7일 뒤 자동 삭제. 코드 변경은 지금처럼 PR이나 커밋으로 남는다.
- 사용자가 필요한 순간(로그인, 인증 코드, 제출 승인)은 워커가 Friday 폼과 승인으로 직접 요청한다.
  작업 중 보낸 관련 메시지도 그 워커로 전달한다.
- 기존 코딩 작업 엔진(진행 표시, 중지, 4시간 한도, 답장으로 이어가기, 샌드박스)을 넓혀서 만든다.
  지금 코딩 작업의 한계: 작업 폴더 접근 불가, 브라우저와 일반 웹 불가, 작업 중 질문 불가.

### 빠른 답변
- 모델 분류기는 넣지 않는다. 낭비를 없애고, 위임할 때는 무엇을 맡겼는지 먼저 한 줄로 답한다.

### 컨텍스트
- 메인은 원칙과 핵심 도구만 둔다. 고정 프롬프트 목표 5~6k자, 항상 주입하는 기억 2~3k자.
- 도구 이름과 인자를 바로 보이게 해서 도구 목록 조회를 없앤다.
- 긴 도구 출력은 메인에 오지 않는다. 위임 결과는 2천 자 이내로 받고 전문은 파일에 둔다.
  예외는 메인의 간단한 웹 검색이다. 한 번에 약 4천~8천 토큰이 스레드에 남고, 뒷단 인수인계로 관리한다.
- 메인이 커지면 답장을 보낸 뒤 뒷단에서 인수인계 메모를 쓰고, 다음 메시지부터 메모와 최근 원문으로 새 스레드를 쓴다.
  사용자에게는 보이지 않는다. 나머지는 recall로 찾는다.

### 기억
- 사용자 말과 답장에 더해 위임 결과의 근거(검색어, 제목, URL, 짧은 발췌)를 기록해 recall로 찾는다.
  페이지 전문, 로그인 뒤 화면, 비밀값은 저장하지 않는다.

### 스케줄
- wake와 체크인을 `schedule` 하나로 합친다: 언제(1회 또는 반복), 무엇을, 어디서 실행할지. 메시지는 같은 봇으로 온다.
- 실행 위치는 메시지 처리 때 판단하지 않는다. 대화 중 만든 1회 후속은 메인, 반복 점검과 백그라운드 일은 임시 대화방이 기본값이다.
  에이전트는 예외일 때만 인자 하나를 넘긴다. 첫 답장 속도에 영향이 없다.
- 임시 대화방에서 사용자에게 말하면 메인 대화에 한 줄을 남겨 답장이 이어지게 한다.
- 체크인은 깨어 있는 동안 3.5시간마다, 조용한 시간 02:00~07:00 제외, 개수 제한 없음. 첫 체크인이 아침 계획이다.
- 할 일 마감 시각 알림은 안전망으로 유지한다.

### 권한과 인젝션
- 스케줄 턴은 채팅과 같은 권한이다. 턴 종류로 규칙을 나누지 않는다. 위험은 메인 턴과 자율 턴이 같기 때문이다.
- 방어는 구조로 한다. 브라우저와 깊은 조사를 하는 워커에는 할 일, 일정, 메시지 도구가 없고, 메인은 결과를 자료로만 받는다.
  메인이 직접 하는 간단한 웹 검색에는 이 분리가 적용되지 않으므로, 도구 설명과 승인 규칙이 방어선이다.
- 도구 설명과 프롬프트는 1차 방어로 다듬고, 되돌릴 수 없는 동작의 승인은 모든 턴에 똑같이 적용한다.

구현 전 확인 결과 (2026-11-23, 서버에서 실측):
- 메인 경량화 가능. 시작 입력의 가장 큰 덩어리는 Friday 프롬프트가 아니라 Codex 기본 지시문(27,750자)이었다.
  `model_instructions_file`로 교체하고 권한·협업·환경 블록, 셸, sleep을 끄면 첫 요청 입력이 15,054 → 웹 검색을 켠 채로
  8,078토큰(끄면 약 5,550, Friday 프롬프트를 넣기 전 기준). 이 상태에서 Friday MCP 도구 호출은 정상 동작했다.
  Codex의 협업 도구와 `exec` 설명 일부는 설정으로 끄지 못했다.
- 위임 지연(상시 app-server, 환율 질문, 각 3회): 메인 직접 검색 중앙값 10.8초, 위임은 첫 한 줄 5.5초에 최종 답 19.5초
  (첫 한 줄 약 5초, 워커 약 10초, 메인 마무리 약 3초). 그래서 간단한 웹 질문은 위임하지 않는다.
  경량 메인이 직접 검색한 환율 질문은 9.5 / 13.6 / 17.4초(중앙값 13.6초)로, 3회 표본에서는 기존 대비 빨라졌다고 볼 수 없다.
- Claude Code 작업에 도구 일부만 연결 가능. 가짜 토큰과 테스트 MCP 서버로 확인: 허용한 승인 도구만 보이고 호출됐고,
  Bash에서는 토큰 파일, 프로세스 정보, 로컬 MCP 포트 모두 접근하지 못했다.
  실제 구현에서는 작업별 토큰으로 서버 쪽에서도 허용 도구를 제한해야 한다. 지금 Friday MCP 토큰은 전체 도구를 연다.
